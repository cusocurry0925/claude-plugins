# 简道云后台配置操作（内部接口 · 内置浏览器）

在 Claude 桌面 App 的内置浏览器（Browser 面板）里打开已登录的简道云页面，用 `javascript_tool` 执行 JS，调用网页端自己使用的 `/_/admin/...` 等内部接口。开放 API（v5）只能读写数据、改不了配置；配置类操作走本 skill。

- 接口清单与已验证的请求格式：[references/endpoints.md](references/endpoints.md)
- 可直接套用的页面脚本：[references/recipes.md](references/recipes.md)
- 平台行为与踩坑：[references/gotchas.md](references/gotchas.md)

## 打开内置浏览器（每次开始前）

1. **工具名**：会话跑在桌面 App 里时是 `mcp__Claude_Browser__*`；云端会话连到用户电脑时是 `mcp__remote-devices__Claude_Browser__*`，后缀相同，用实际存在的那组。只看到 `enable__mcp__remote-devices__Claude_Browser` 时先调用它开启。工具是延迟加载的，就用一次 ToolSearch 按前缀整批加载（如 `{query:"mcp__remote-devices__Claude_Browser__", max_results:64}`）。会话里有 `built-in-browser` 技能时先读它。
2. **开自己的标签页**：先 `tabs_context`。面板没开（`browserOpen:false`）时，`navigate {url:"https://www.jiandaoyun.com/dashboard"}` 会打开面板（落在 `seed` 标签）；面板已开时，`tabs_create` 拿新 `tabId`，再 `navigate {url, tabId}`。之后每个调用都带这个 `tabId`。面板已开时不要用 `preview_start`：它总是把 `seed` 标签跳走并切到前台（2026-10-23 实测，不会新开标签），可能冲掉用户正在看的页面。
3. **站点授权**：工具回复站点未允许时，有 `request_access` 就对 `https://www.jiandaoyun.com` 申请（长期用选 `scope:"site"`），等用户批准后重试；被拒就停下告诉用户，不要绕。
4. **登录**：内置浏览器是独立的浏览器配置，不带 Chrome 等其他浏览器的登录；登录后在桌面 App 的各会话间保留。页面跳到 `portal.finecloud.com/portal/signin` 说明没登录：请用户在 Browser 面板里自己登录，绝不代填密码。请用户动手前先 `tabs_context` 确认面板在显示；面板被隐藏时，请用户按 Cmd+Shift+B（Windows 为 Ctrl+Shift+B）调出。
5. **就绪检查**：运行 recipes「R0」，`host` 是简道云域名、`hasCsrf:true` 才开始干活。
6. **够不着时**：内置浏览器运行在用户电脑的桌面 App 里，App 关闭、电脑睡眠或离线时工具调不通——如实告诉用户，不要反复重试。内置浏览器打不开 `file://` 和 Claude 自己起的 localhost 服务。

## 工作规则（必须遵守）

1. **生产默认只读。** 任何写操作先向用户说明改什么、改哪个应用，得到明确确认再执行；能先在测试应用做的一律先做测试应用。新建 webhook / 启用助手 / 改权限组等「持久配置」必须有用户针对该操作的明确授权。
2. **绝不删除业务数据**；删字段 / 删配置也要单独确认。
3. **三段式写入：** 读基线 → 带防护的写入（逐项核对「ID 对得上且当前值等于预期旧值」，任一不符整批放弃）→ 重读定义与基线逐项对比，只允许预期差异。
4. **用自己的标签页**（`tabs_create` + `navigate` 新开、按 `tabId` 操作），不要动用户正在用的标签页；标签被关掉后重新开；做完把自己开的标签留给用户还是关掉（`tabs_close`），按用户意思办。
5. **CSRF 令牌只留在页面内存**，从 `meta[name=csrf-token]` 读取，绝不输出；apiKey 只放本机文件（如 `~/.config/jdy/*.key`，`chmod 600`），不打印、不写进仓库。
6. **跨应用复制时保留目标应用自己的关联对象**（`relationship`、`aggVars.*.relationshipId`），这些是每个应用独有的 ID。
7. **从生产复制出来的应用**：助手、数据推送可能仍指向生产（例如推送地址是生产助手的 webhook），启用前必须改指向。
8. **登录是用户的**：不登出、不改密码、不动与任务无关的账号设置。

## 输出与执行注意（内置浏览器，2026-10-23 实测）

- `javascript_tool` 按 REPL 语义执行：顶层 `await` 可用，**最后一个表达式**的值按 JSON 返回（不要写 `return`）。
- 返回长度：7KB 以上（2,400 个汉字）原样返回、未截断；结果里有 `=` `&` `?`、URL 也不会被拦截，无需替换或打码。大结果仍先放 `window.__xxx`，按需分批取，别一次灌进上下文。
- 单次执行 **45 秒超时**；超时后脚本可能仍在页面里跑，先检查页面状态再决定是否重跑。大批量（如 100+ 张表对比）用 `window.__job=(async()=>{…})()` 启动后立即返回，结果写 `window.__xxx`，再用 `javascript_tool` 轮询（`computer` 的 `wait` 单次最多 10 秒）。
- 同一标签页内，`window` 上的变量跨调用保留；页面刷新 / 跳转后全部丢失。长期复用的脚本存 `sessionStorage`（按标签页隔离），用 `new AsyncFunction(...)` 执行（见 recipes「R0」）。
- 点击优先用 `find` / `read_page` 给的 `ref`（落在元素正中）；用坐标点击时，坐标按最近一次截图的坐标系，换算见 gotchas。
- 面板被隐藏时页面按后台页运行，计时会不准；读页面优先 `get_page_text` / `read_page`，少用截图。

## 常用流程

- 开始前就绪检查、列应用 → recipes「R0」
- 只读自检（换环境 / 换账号后先跑一遍）→ recipes「R14」
- 聚合表加数据源 / 改指标公式 → recipes「R12」
- 批量改字段名 → recipes「R2 设计器保存拦截」
- 加字段 / 改下拉选项（设计器无改动时「保存」禁用）→ recipes「R3 直接提交表单定义」
- 两个应用之间同步表单 → recipes「R6」；同步流程 → recipes「R7」
- 新建数据推送 / 启用助手 → recipes「R8」「R9」（需用户授权）
- 只读复核（流程节点权限、字段联动、聚合表配置）→ recipes「R1」「R5」「R10」
